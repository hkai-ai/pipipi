## Runtime v1.13

同次编译与复核增加可选的像素轮廓依据：单一背景上可分离内容带的分段上下缘来自真实附件，不是文字基线或形状判定。复杂背景跳过，弱对比细节仍看原图；不把坐标写入正式模板。请求字段先观察后取舍。此为宿主辅助观察能力，来源原文没有该测量脚本；不增加模型调用或更换模型。

真实失败样本暴露的宿主修正：文字复核的两个必填证据组在请求级 Schema 中分别限定可引用路径；解码后无损还原十九项原报告。复核上下文列出选定视觉事实与正式同名字段的精确差异，不自动修正事实。该传输与反馈调整不新增图像判断规则。

证据范围独立于 250 项补丁路径上限，避免大候选截掉正式视觉约束而产生空枚举。八轴召回证据在传输中采用具名必填对象，解码恢复原来的逐轴报告，不能以父对象或少数轴代替全部检查。

编译与复核在同次请求中使用完整总览和最多一张完整内容观察图；只去除近似背景边缘，不切断整行文字或组件组。淡色细节和原留白以总览为准；不新增模型调用，不改变图片引用。预处理继续沿用固定区域细节模式。整段排列与单个字形分别观察，不预设弧度、文字颜色或素材类别；实际观察与成图效果仍需真实验收。

此版本按来源分析合同补齐独立观察、文字分类、翻译关联、默认语言与输入模式、动态来源、来源隔离和完整重绘检查。共同 semanticModel 唯一拥有 Prompt 与 runtime，程序投影为草稿；原始 fieldEvidence 与选定 mediumComposition 分开保存。

撤销此前六轴排版及逐轴强制写入视觉合同的适配。来源 layout、position 为描述文本，没有固定六轴或三点几何要求。删除和待辨识文字仍需保留观察。结构通过不证明视觉理解正确。

八份来源业务文档保持全文打包，构建器核验 manifest 的全部 26 个文件。Python 校验行为在服务端 TypeScript 合同中对应；脚本、注册表、磁盘交付与工作台权限不进入无 Tool Agent。当前仍是单图服务，不复制原批量交付或历史局部返修接口。

复核沿用独立会话与十九项报告，有界补丁绑定输入计划摘要，服务端合并后执行全部校验。该调用编排是宿主适配，不是原文要求的独立模型调用次数。现有模型、思考配置、预算、公开 Gallery JSON 和审批流程保持不变。

## 观察与规则取舍对账

原始视觉依据通过内部 `visualSelections` 逐项记录保留或舍弃理由，并引用正式约束；独立复核分别检查图像观察、取舍和执行句，不能只核对已有引用。该对账不预设形状，也不要求所有观察成为冻结规则；原始观察遗漏与舍弃合理性仍依赖看图判断。

`visualSelections` 是宿主新增的内部审计字段，不是来源原有字段或视觉判断规则。保留项引用正式媒介或数组条目，舍弃项不带冻结引用；不从正式约束回填原始依据。复核沿用十九项报告，在 `visualContractRespectsInputs` 中按三组传输证据，模型重新看图后在同一次补丁内修正遗漏及依赖。来源 26 个文件和八份内嵌原文的摘要不变，公开模板、模型选择、思考配置与调用预算不变。
