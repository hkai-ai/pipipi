# Domain Docs

本仓库使用 single-context 领域文档布局。

## 工作前读取

- 先读根目录 `CONTEXT.md`，使用其中的项目范围和共同语言。
- 再读 `docs/README.md`，从文档地图找到当前任务的设计、开发或发布文档。
- 检查 `docs/decisions/` 中与当前任务相关的设计记录。目录或相关记录不存在时继续工作，不需要预先创建。

## 使用规则

- Issue、规格、测试名和设计讨论使用 `CONTEXT.md` 中的领域词，不引入被明确避免的同义词。
- 当前任务需要的新概念若不在共同语言中，先判断它是否属于真实领域缺口，再通过 domain-modeling 流程更新 `CONTEXT.md`。
- 规格若与已有设计记录冲突，必须明确指出冲突，不能静默覆盖。
- `CONTEXT.md` 记录长期稳定的目的、范围和术语；Implementation、命令与发布步骤留在对应专题文档。
