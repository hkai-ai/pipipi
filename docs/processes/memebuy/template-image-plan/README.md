# 图片替换方案

`template-image-plan/v1` 使用真实图片附件与固定 Runtime Skill 输出未批准的替换策略，不生图、不上传。系统提示将约 27KB Skill 正文置于规划与修正指令之前（`skillFirst`），并在 OpenAI 协议下绑定稳定 `prompt_cache_key`（`template-image-preparer:v3`）共享前缀缓存。调用方必须展示完整策略，等待第一次人工确认。

规划和字段修正共用 768 KiB 的 Base64 视觉附件预算。超出预算时，按原顺序将总览和各局部图转为 WebP，必要时等比缩小；用于审核、保存和计算摘要的原图保持原字节。

模板制作的新方案默认保留原图的透明区域，明确指定的背景要求优先。背景随方案批准固定，旧方案需重新规划才能匹配原图。

模型返回后独立记录 `plan_validation`，收集固定字段的结构问题与具名业务规则。对象候选可修正时，只在原 240 秒预算内执行一次 `plan_correction`：若生图操作未覆盖方案中的组件，修正请求列出未引用与不存在的组件 ID，交由模型依据原图和各组件的特征权限修正。请求级严格 Schema 限定可替换的顶层字段，Agent 重新读取原图及固定 Skill，返回字段值的 JSON 编码补丁；程序保留其余字段，合并后重跑全部结构和业务校验。未知顶层字段、非对象、超预算候选及模型执行错误直接失败，不重新生成完整方案。修正不改变审批门禁。

`template_strategy_diagnostic` 日志只记录 runId、阶段、最多 16 个规则码与固定字段名，不记录原始异常、URL、候选正文或模型回答；诊断 Sink 失败不改变业务结果。`plan_persistence` 仅在完整校验通过后开始。历史运行未保存候选及规则诊断时，不能从通用 `AGENT_FAILURE` 推断具体字段。

编排、来源和恢复边界见 [审核后编译模板](../template-from-source/README.md)；输入输出见 [API 文档](../../../api.md#模板图片生产与两次审核)。
