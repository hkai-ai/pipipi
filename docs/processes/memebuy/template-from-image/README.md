# 图片转模板

文字排版沿用来源 `approved-image-analysis` 的逐区分析要求。保留或可编辑文字的内部 `layoutRefs` 按整行形态、基线、字形、间距、对齐层级、位置引用正式 `visualContract`，程序投影为 `textRegions.layout`；删除或未解决文字为 null。独立 `textEditLayersComplete` 同时引用文字区域和正式约束并重新看图，必要时在原补丁预算内修正。平直、曲线和竖排按实际附件判断，不从预处理计划推测，不将单字歪斜当作基线弧度。公开 JSON、Process ID、模型和调用预算保持不变；存量模板需重新编译才能补齐遗漏事实，不能靠部署追补历史版本。

`template-from-image/v1` 将用户提供的一张参考图编译成可编辑的 Gallery v2 `PROMPT` 草稿。当前对接 Memebuy 素材箱提取 Worker，人工确认后保存草稿；部署与真实页面验收另行完成。Pipipi 独立测试与 JSON 下载保留。公开字段、响应和错误统一见 [API 文档](../../../api.md#图片转模板)。

## 执行方式

1. 严格验证业务输入，拒绝运行配置与额外字段。
2. 复用受控 HTTPS 下载器：校验全部 DNS 地址并固定连接 IP，禁止私网和重定向；下载上限 20 MB、30 秒。
3. 解码静态 PNG/JPEG/WebP，最多 4000 万像素、宽高至少 64；按 EXIF 方向处理，生成最长边 1600 的 PNG 视觉附件。
4. 无 Tool Pi Agent 使用固定 `meme-template-json-compiler@v1.8` 读取完整八份来源业务文档，首轮只输出正式草稿和引用分析计划，第二轮在新 Session 独立看图复核，直接返回必要补丁与十九项最终报告。服务端合并并投影为完整候选，执行全部校验。两轮均使用 medium 思考，复核逐一提供八轴观察，避免只检查已有槽位。首轮启用 JSON 模式，复核启用严格 JSON Schema；禁用 SDK 内层自动重试与自动压缩。复用服务端 `PI_PROVIDER` 和现有凭证；可用 `TEMPLATE_MODEL` 单独指定模板模型，未设置时 OpenAI 默认使用 `gpt-5.4`，其他供应商沿用 `PI_MODEL`；所选模型必须声明图片输入能力。
5. 对已完成响应仅允许去除 Markdown 包裹或一个多余的末尾闭括号，不补造字段；随后由固定 Gallery Schema 和本地语义规则验证草稿、槽位、推荐项、占位符、身份目标和服装归属。同时检查候选六门禁、九轴身份权限、文字路由、三个推荐项的实际代入、视觉事实保留、开放事实隔离及 semanticModel 的一致性。独立复核原样回传服务端输入计划摘要，提供必要字段补丁和针对最终候选的真实引用及具体观察；服务端验证摘要、应用补丁并绑定最终候选摘要，不代填结论。正常两次模型调用，仅首轮 JSON 或候选结构无法读取时允许一次重新编译，最多三次；复核失败不继续请求模型，网络或模型调用异常不自动重投。
6. 服务端注入状态、原图引用、最接近原始宽高比的固定尺寸等字段，返回通过输出校验的候选。`analysis` 和 `review` 只用于当次校验，不写入正式结果。

模型传输对组件、空间关系、八轴覆盖、六门禁、推荐项与标签使用紧凑行；featureAuthority 使用 {owner,basis,evidence,runtimeFactRef}，复核项使用 {passed,evidence:[{path,observation}]}，避免多层位置数组混淆。仅 replace_identity 槽位填写完整九轴，其他槽位返回 null。证据遵循来源的非空与具体性要求，取消四字符下限，模型证据保留 96 字符上限；正式视觉事实不受此限。服务端无损展开，仍检查缺项、错误类型、全部业务门禁与最终候选。

给模型的草稿 Schema 显式要求每个槽包含文字模式及三个推荐项，与业务校验保持一致；缺字段时修正反馈包含固定 Schema 中的属性名，避免只收到 `required` 却不知道应补哪个字段。

视觉事实仅在正式 visualContract 中生成。空间关系用 relationIndex，后端事实与特征执行要求用 {field,index} 引用已有视觉条目。服务端生成 semanticModel、mediumComposition、事实副本、默认值副本及推荐项完整代入句，消除重复生成的文字漂移；不会自动追加冲突句子。失效引用给出源路径、目标路径及有效索引范围，进入原有修正预算。修正上下文直接读取引用计划，即使关系引用失效仍保留槽位约束及具体目标路径。修正请求额外列出关系差异与每槽模板接管的特征，帮助检查推荐项冲突；这些业务上下文不进入公开响应或日志。投影只保证对应关系，不证明图片理解、引用选择和推荐项语义正确。

目标范围仅在 targetScopes 声明覆盖的组件 ID，程序派生 componentGraph.targetIds 和 slotEvidence.componentIds。每个正式目标都必须有完整有效的范围；同一输入绑定多个目标时分别保留各目标的组件，避免人为制造全连接。模型仍负责让目标的 role/region 与视觉规则描述这一范围。

槽位取舍直接复用来源原文：优先选择 2–4 个高价值编辑轴，完整覆盖审查后允许单槽。独立复核检查未入选内容及固定理由，包括主视觉配色、标志物、关系文字和嵌套内容；不把单槽、装饰类别或原图默认值当成固定依据。新增编辑轴时同步 Prompt、槽位、绑定、分析、推荐项代入及开放值约束，不对所有图片强制添加同一槽位。源码对齐可运行 `node --import tsx tools/build-template-skill.ts <已审查来源目录> --check`；测试同时逐文档核对来源摘要。

候选结构可读取后，草稿语义、分析一致性问题与独立看图发现的问题由第二次调用统一处理，不能因 needsReview、占位符或标签等单项错误提前消耗修正机会。最终交付仍必须通过全部校验。来源特征可以声明由输入接管，只需在正式约束中落实；禁止锁回具体原图特征。

独立复核携带首轮计划、输入摘要、程序校验问题及依赖上下文，不传生成者的自评报告。复核者先独立看图，再只修改必要字段并给出针对最终完整候选的十九项报告；服务端应用补丁后重新绑定摘要和执行全部校验，不默认追加另一轮复核。没有问题时返回空补丁；明确的遗漏违规仍须拦截，无法修正的候选直接失败。仅已识别身份要求专名与默认值一致，未识别身份使用可见描述，不因校验要求猜测姓名。

复核引用检查字段是否存在，合法的 null、false 或空集合可作为能力未启用等否定观察的依据，不等同于丢失字段。不存在的可选字段应引用其已有父对象并说明缺项；未知路径仍拒绝，诊断给出具体路径。引用有效不代表语义成立，草稿规则、十九项结论和候选摘要检查保持独立。

结构完整的候选使用字段补丁修正：Agent 同时获得补丁格式和与首轮相同的引用计划 Schema，返回必要字段的替换值及完整的最终复核报告；服务端复制上一版计划后应用有界补丁，未涉及的源字段逐值保留，派生字段按依赖重建。路径必须位于已有 analysis 或 draft 字段，禁止越界、重复和互相覆盖；增删内容通过替换父对象或数组完成，视觉数组重排时同步引用索引。应用后仍执行全部合同、语义与最终复核报告校验。仅前一版结构无法读取时才完整重新编译，修正次数上限不变。

送入复核的问题清单先聚合草稿语义、组件八轴覆盖和特征权限依据，再尝试引用投影；引用失效不得掩盖这些不依赖派生字段的既有检查。复核证据可引用请求中已有且在最终候选保留的父字段，新增或移除内容后的存在性仍由最终校验确认。

独立复核使用请求级严格 JSON Schema，不能只依赖提示词中的 Schema 或普通 JSON 模式。Chat Completions 写入 `response_format.json_schema`，Responses 写入 `text.format`；不支持的协议在模型请求前失败，不自动降级或重投。`changes` 每项固定为 `{path,valueJson}` 对象，`valueJson` 保存替换值的完整 JSON 编码，避免严格 Schema 中使用任意对象属性。请求摘要固定为本次计划摘要；补丁路径从现有安全字段按层枚举，最多 250 项，优先保留父容器，深层修改可以替换父对象或数组。复核证据只引用最终候选的正式字段，不引用已被投影移除的计划根字段。Adapter 解析后恢复原 `{path,value}` 补丁，再执行既有路径、输入摘要、十九项复核和最终业务校验；不兼容的结构及非法 JSON 继续拒绝。原 Skill 业务文档和公开 Gallery JSON 不变。

Process 总时限 480 秒，取消复用共享 Runner 和 Session。运行活动为 `template_image_loading`、`template_compilation`、`template_correction`、`template_review`、`template_validation`，日志不含图片 URL、字节、Prompt 或完整候选。需要真实视觉模型和可访问参考图；不需要 FAL、OSS 写入、Python、注册表或 Memebuy 服务。

生产日志的 `template_diagnostic` 按 `runId` 关联编译、修正、复核和校验问题；包含阶段内尝试次数，以及 JSON 语法、结构、业务合同或执行异常分类。结构问题额外记录最多 16 条固定错误类型及字段路径；仅保留静态合同字段和有界数组索引，动态槽位、标签与未知键替换为 `*`，不记录原始错误消息或模型内容。诊断写入失败不影响结果或修正预算；该事件只进入运维日志，不加入公开输出或 Run Record。

## 调用与验证

通过主 API 的 `POST /execute` 调用本 Process，输入与输出见 [API 文档](../../../api.md)。本地独立测试页和专用验收脚本已移除。

2026-09-11 改由 Memebuy `/admin/gallery-template-sources` 素材箱接入，不恢复 `/template-lab`。运营选择素材后立即排队，现有提取 Worker 按资产重新签名并审核，再调用本 Process。Memebuy 配置中心的 `REMOTE_RUN_TEMPLATE_BASE_URL` 可覆盖模板服务地址，留空时沿用共享 RemoteRun 地址；模型仍由 Pipipi 配置。用户私图返回的 cover/referenceImage 不作为永久模板地址；确认后由 Memebuy 原导入器保存投稿人的 DRAFT，不自动上架。该链路只在启用提取的非生产环境开放；本次不迁移生产素材、不部署。

确定性验证：`npx vitest run test/template-from-image.test.ts test/template-agent.test.ts test/template-quality.test.ts`。覆盖真实 HTTP、真实图片解码、固定合同、拒绝越权字段、修正预算、异常净化以及 SDK 图片附件传递；视觉模型使用替身。完整检查按仓库默认四项执行。

人工验收时使用自己有权处理的公网图片，分别检查身份替换、文字编辑和复杂多人图。成功必须同时满足：画面理解正确、槽位有价值、推荐值实际可替换且不与固定视觉约束冲突。确定性测试不证明这些视觉质量指标。
