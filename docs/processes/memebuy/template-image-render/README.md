# 审核后生成图片

`template-image-render/v1` 只接受已确认方案的生产项与摘要，生成一张 PNG 并返回待审图片。第二次人工确认之前不上传模板 OSS。恢复相同生产项不再次提交图片生成。

新成图默认使用既有 OpenAI 图片中转站，以原图字节提交单次 multipart 编辑，固定 `gpt-image-2.5-flare`、`quality=low` 与 PNG。配置复用 `resolveModelGateway(..., "image")`，独立图片配置优先于共享网关，不受 CRT 的 `IMAGE_PROVIDER=fal` 影响；缺少网关配置时启动失败。方案背景原样传递，不改写已批准指令。透明 PNG 必须同时包含可见像素和透明像素才可进入审核。

提交前持久保存渠道与未知状态，中转站响应原字节先落盘再校验；同一成图恢复只读取已保存的结果，没有结果的未知提交须人工对账。旧 FAL 模板端点 `openai/gpt-image-2/edit` 在托管与提交前拒绝新的透明背景请求，返回 `DEPENDENCY_FAILURE`。该检查仅针对新提交。无渠道字段的历史已提交记录仍属于 FAL，只查询原 requestId；完成后结果接口明确返回 400/422 时保存终态拒绝。任何失败均不自动切换渠道或重新付费。明确失败后，运营可在原批准方案下用新 `renderId` 发起一次人工重做，旧记录原样保留。

编排、来源和恢复边界见 [审核后编译模板](../template-from-source/README.md)；输入输出见 [API 文档](../../../api.md#模板图片生产与两次审核)。
